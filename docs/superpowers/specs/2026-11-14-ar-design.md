# AR "See it in your room" — design

**Date:** 2026-11-14 · **Status:** approved in chat, waiting for spec review
**Based on:** spike with Ingenuity (`ar-test.html`), which worked on an iPhone (Quick Look) and on a laptop (3D + QR).

## Goal

On a device's profile, the kid can spin the real NASA 3D model and, on a phone, place it in their room at real size.
On a laptop (no AR), a QR code opens the same device on the phone.

## Scope

11 devices that have a NASA model. Devices without `model3d` show no 3D tab.

| Device id | File in `public/models/` | NASA source (github.com/nasa/NASA-3D-Resources, `3D Models/…`) | Notes |
|---|---|---|---|
| `eagle`, `falcon` | `lunar-module.glb` | `Apollo Lunar Module` (0.7 MB) | ~7 m tall at real size; kid can pinch to shrink |
| `opportunity`, `spirit` | `mer.glb` | `Mars Exploration Rover - Opportunity (MER-B)` (36 KB) | Low detail. Swap for a Blender export of `Spirit and Opportunity.blend` later |
| `ingenuity` | `ingenuity.glb` | `Ingenuity Mars Helicopter` (2.0 MB) | Already in repo from the spike |
| `insight` | `insight.glb` | `InSight Cruise Lander (panels deployed)` (3.9 MB) | Compress to < 3 MB |
| `viking1` | `viking.glb` | `Viking Lander` (1.8 MB) | |
| `near` | `near.glb` | `NEAR Shoemaker` (0.7 MB) | |
| `dawn` | `dawn.glb` | `Dawn` (0.9 MB) | |
| `pioneer10` | `pioneer10.glb` | `Pioneer 10` (2.0 MB) | |
| `kepler` | `kepler.glb` | `Kepler (A)` (2.0 MB) | |

Out of scope: models for `reflecto`, `pathfinder`, `surveyor3`; the Blender export for the rovers; hosting the site (needed for the QR to work outside the local network, separate task).

## Data

- `src/content/types.ts`: add `model3d?: string` to `Device` (path under `/models/`).
- `src/content/devices/*.ts`: set `model3d` for the 11 devices above.
- `src/content/i18n/en.ts` (`profile`): new strings: tab label `3D`, AR button `See it in your room`, QR caption `Scan with your phone camera to see me in your room`, credit `3D model: NASA`, loading text.

## Components

**`src/components/DeviceModel.tsx`** — one job: show one device's model.
- Props: `device: Device`.
- Dynamically imports `@google/model-viewer` on mount, so its code (and its own copy of three.js) loads only when a 3D view opens.
- Renders `<model-viewer src alt camera-controls ar ar-modes="webxr scene-viewer quick-look" ar-scale="auto">`.
  - `auto-rotate` only when `prefers-reduced-motion` is not set (existing `useMedia` hook).
  - `ar-scale="auto"`: opens at real size, kid can pinch to resize.
  - AR button: the house `Button` component with `slot="ar-button"` (≥ 44 px, semantic tokens).
- After load, if `canActivateAR` is false: show a QR (`uqr` `renderSVG`) of `${location.origin}/?ar=<device.id>`, with caption, white quiet zone, `role="img"` + `aria-label`.
- Credit line linking to NASA 3D Resources.
- Load error: show a short text message instead of a blank box.

**`src/screens/Profile.tsx`** — tabs become `photos | science | model`; the `model` tab exists only when `d.model3d` is set and renders `<DeviceModel device={d} />`.

**`src/screens/ArView.tsx`** — the page a phone opens from the QR: device nickname, `<DeviceModel>` full height, and a link back into the app (`/`). No game state needed, so locked/secret devices still open.

**`src/App.tsx`** — before picking a screen, read `?ar=` from `location.search`. If it names a device in `deviceById` **with** `model3d`, render `ArView` (lazy). Anything else (unknown id, no model) is ignored and the app starts as normal. This is the only input from outside the app, so it is checked against `deviceById`, never used as a path.

## No runtime network calls (CLAUDE.md)

The NASA models use Draco compression. model-viewer would fetch the Draco decoder from Google's CDN by default.
- Copy `node_modules/three/examples/jsm/libs/draco/gltf/*` to `public/draco/`.
- Set `ModelViewerElement.dracoDecoderLocation = '/draco/'` before the first model loads (in `DeviceModel`).
- Check in the browser's network log that opening a model makes no request outside our origin.

## Dependencies

Already added in the spike: `@google/model-viewer@4.4.0` (with `overrides` so it uses the project's `three`), `uqr@0.1.3` (QR as SVG, no dependencies). No new ones.

## Clean-up

Delete `ar-test.html`, `vite.ar-test.config.ts`, and the `ar-test` entry in `NASA/.claude/launch.json` once the 3D tab works.

## Testing

- `npm run build` passes (type check + build); `npm run lint` clean.
- Browser pane, phone and desktop widths: 3D tab shows only for the 11 devices; model loads; QR shows on desktop only; `/?ar=ingenuity` opens `ArView`; `/?ar=nope` and `/?ar=reflecto` start the normal app.
- Network log: no requests outside our origin when a model opens.
- On a real iPhone (user): AR opens from the profile tab and from a scanned QR.
- Self-check for the `?ar=` parsing, done in the browser (the project has no unit-test runner and runs Node 20): valid id with model, id without model, unknown id, `__proto__`.

## Risks

- Large devices (Eagle, Falcon ~7 m) fill a room at real size; pinch-to-shrink covers this.
- The rover model is low detail until someone exports the better one from Blender.
- The QR only works when the phone can reach the site: same network for local dev, a hosted HTTPS link for the demo.
